## 对 Cosmos harness 的建议

1. 有明确接口和确定性验收的小模块先验证 low 路线，复杂设计和难以定位的失败按需提高推理。
2. `finish_reason=length` 或缺少完整产物直接标记未完成；不送入集成。按任务拆分、推理设置和输出额度处理，再执行有界重试。
3. 接口写到可判定：导出形态、字段、边界不等式、状态不变条件。模糊需求会造成额外调用和错误归因。
4. 确定性检查负责拦截可表达的错误；失败摘要只发给相应模块，修复后重验受影响部分。
5. 先验证正常质量下的单位产出费用与关键路径，再把 ¥100/6h 或 ¥200/12h 写成产品指标。

## 复现

运行环境为 Node.js 22.22.2，无第三方运行依赖。`DEEPSEEK_API_KEY` 仅从当前进程环境读取，不写入文件；脚本不会输出凭据或保存原始推理内容。

- `COSMOS_PROBE_EFFORT`：`default`、`low` 或 `disabled`。
- `COSMOS_PROBE_PHASE`：默认 `comparison`；`diagnostic` 使用已保存的失败样本做定向修复。
- 执行：`node probes/2026-10-01-deepseek/probe.mjs`。

脚本会计入当前目录既有结果中的费用及未知请求预留，达到共享 ¥10 上限后拒绝新调用。复现会产生新的费用，应纳入原验证总额。
