## 复现与目标

主阶段保存 4 并检查成功，之后重新保存 5，确认界面显示已保存 5。旧执行器采用更早的匹配行，仍报告关闭检查点为 4 并打开第二个进程。新执行的通用持久浏览器系列应当在第一次关闭前取得新的 savedSnapshot 可见文本，与原检查点声明的 expected 比较。若玩家保存 4 后继续玩到 5 而没有再次保存，应允许通过关闭检查，随后在同一来源与用户目录重开，恢复 4。

## 实施范围

- 新构建的 generic 系列冻结版本化关闭核验选择，进入既有系列摘要。历史未选择报告和 transfer 系列保留自己的读取和验证契约；执行和事后校验都使用可信 host 传来的固定系列。
- 所有作者步骤、媒体采样和渲染采样结束后、主进程清理前，在同一页面按冻结选择器执行一次有界只读 visible text 观察。存储实际观察、来源绑定及对应截图，没有新增作者步骤或输入动作。沿用原有工作期限、取消和清理余量。
- 新选择缺证、错误来源、不可读或观察不符均不能放行重开，必须正常回收已启动的进程。保留能区分实际值不符和无法取得证据的事实。成功与失败诊断使用同一条检查点证据标准，不能把历史匹配行当作新样本。保留原有的真实进程退出、重新启动、同源与同 profile 要求和重开后的可见断言。
- 本检查只证明关闭时界面上的已保存状态；重开后仍须验证实际恢复结果。主阶段当前游戏进度可以与存档不同。原著步骤、验收 ID 和 200 步上限继续有效。
