# COS-175 · 被拒设计写入后的原预算压缩

任务：[COS175 / #176](https://github.com/lrfluobida/Cosmos/issues/176)。源码基线 `d218e6388e11cee777433bf5a30ad01cd38779fc`；本记录仅覆盖免费 SOURCE 实施，独立审查与唯一 merger 集成另行记录。

## 问题与范围

R28 在 5 分 37 秒后失败，尚未捕获、独审或进入美术、编码。一次压缩后输入降至 73663 bytes，但两次大计划完整写入被正确拒绝，旧的 `isError` 排除条件跳过了后续预算压缩。普通输入增至 155403 bytes，作者余额 293508µ 连输入报价 310806µ 也无法承担。原设计分配 1125000µ 和独审预留 375000µ 均不变。

已批准计划中的离线容量依据：第一次拒绝后，真实 SDK 摘要输入 56937 bytes / 8192 输出预留为 179410µ；仅把历史真实摘要作为大小夹具时，下一输入 65971 bytes / 8192 输出预留为 197478µ，两者合计 376888µ，小于当时余额 384972µ。这是容量证据，不保证新摘要质量或真实模型修复成功。R28 保持失败、关闭，不修改或重开其账本、产物或原生记录。

## 实现边界

- 原主机草稿保护检查只在当前设计与计划均有效、候选验证失败且尚未提交时抛出 `PreservedDesignDraftError`，诊断文字及文件保持原样。
- 普通入口只为已有草稿保护策略选择 `ordinaryDesignRejectedWriteCompaction`。factory 只把它传给原普通 design 作者的预算压缩会话；旧策略、其他角色和验证模式不选择。
- Pi 在实际可信工具执行抛错处记录调用 ID、工具名和原诊断；仅原 `write`、`edit`、`write-game-plan`、`write-game-design` 可记录。模型提供的名称、JSON 或诊断字符串不能创建错误实例身份。
- 轮次必须是完整工具调用/结果批次，且所有错误都与记录逐字匹配；混有越权读取或任意其他错误则保持原排除行为。provider 失败也不进入该边界。工具仍以原生 `isError: true` 返回。
- 摘要沿用原请求准入、实际费用、请求次数、输出上下限、冷却/增长条件、原 deadline 和独审预留。压缩后核验最新完整调用及全部结果仍在 SDK 原生投影中；未保留则失败，不继续派发。原 journal 不重置。

这只扩展 [COS125 的非错误边界](cos125-design-context-budget.md#41-成功工具边界)，不新增重试、额度、provider 或会话。摘要仅供后续真实作者修复；结构检查、捕获、独审与真实游戏验收仍各自必需。

## 验证与限制

新增 `tests/providers/rejected-design-compaction.test.mjs` 使用真实 factory、预算控制器、文件写入保护、Pi 和锁定 SDK，仅模型传输受控且禁用网络。正例建立有效中文草稿、生成大拒绝候选、在剩余额度 384972µ 下压缩并派发后续合法写入，检查完整错误调用/结果及历史 journal 保留、拒绝时草稿字节不变、真实预留/结算及独审余额。摘要按全部预留结算，避免依赖廉价合成费用。

原生正例测得摘要输入 66435 bytes、随后普通输入 49871 bytes；这与 R28 使用不同合成上下文，仅证明源码边界和预算接线，不冒充实际模型生成。负例覆盖越权读取、混合错误、伪造错误名与相同诊断、provider 失败、预算不足、deadline 到期、未选择开关。host 测试覆盖当前保护策略选择及旧策略不选择。

首次聚焦运行新增原生 8/8、host 选择 2/2 通过；同文件原 COS161 保稿检查 8/9 通过。唯一失败 `COS161 unsafe companion blocks partial construction and missing classic output cannot disable protection` 在原基线五个生产文件下同样复现：假作者再次执行开头的无效写入时已有有效草稿而被拒绝。本卡保留该旧夹具不改，不将其列为本次通过证据。

最终增补精确调用/结果与 journal 断言后，新正例及原 COS125 非错误压缩代表 2/2、0 skip；原基线加载器运行新正例时，在拒绝边界未新增 checkpoint 的断言失败（0 != 1），验证复现能区分旧行为。`npm run typecheck`、`npm run build`、`git diff --check` 均 exit 0。全部修改文件经严格 UTF-8 解码、LF 检查及原中文逐行保留检查；未进行任何付费调用或真实 run/ledger 写入。
