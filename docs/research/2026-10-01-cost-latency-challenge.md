# Cosmos 成本与时长二次穿刺

日期：2026-10-01。用户要求重新检验 ¥800 与 48h；完整经典版内容及质量要求继续作为目标。

决策更新：用户选择正式单次生成验证硬上限 **¥200/12h**，以 **¥100/6h** 为优化目标。本文中的推算和待测项目保留其证据等级；上限已确认不代表完整生成已实测通过。

## 1. 结论与证据等级

- ¥800 缺少工作量推导，不能当作必要成本；48h 是上一轮停止条件，尚无实测关键路径依据。
- 已确认 **¥100 / 6h 为优化目标，¥200 / 12h 为正式单次验证硬上限**。当前没有完整游戏在这些约束内达标的实测证据。
- 已复核官方单价，并重新计算调用额度；已检查现有 spec 的串行路径与验收约束。
- 用户随后提供 API Key，已通过临时进程环境执行 31 次真实模型请求，保守高峰价估算 ¥0.721771。局部规则生成、定向修复和简单图识别已有证据；完整游戏、pi SDK 集成及美术服务仍未实测。详见 [真实探针报告](../../probes/2026-10-01-deepseek/README.md)。

新增发现：默认 high 推理配合 8,192 输出 token 限制时，两次局部生成被截断。相同提示版本下，low 整组 44.403s、默认模式 106.631s；两者均有失败，不能只比较时间来选择模式。一次实际时间校验失败通过 1.677s 的 low 定向修复后通过全部对应检查。应优先验证分任务推理与确定性验收，而不是一律采用同一推理配置。

## 2. 上轮估算中缺少的依据

1. **Token 用量没有从任务推导。**70M 输入、8M 输出没有对应模块数、请求数、上下文大小、推理输出及修复记录。应从实际运行计数，不能把这些示例数字当作需求。
2. **图片数量没有资产分解。**460 张候选图没有区分独立角色、共用部件、关键姿态、场景、UI 和废稿率。程序动画可以减少独立图片需求，但减少多少尚未验证。
3. **时限没有关键路径。**模型等待、编码、素材、集成、试玩与修复没有分项测量。并发仅能缩短独立任务，不能直接把总时间除以 agent 数。
4. **预算上限与预计消费混在一起。**合理的停止额度应留出实测返工余量；正常开销要作为另一项结果报告。

## 3. 调整生产方式

### 3.1 美术按部件和关键姿态组织

- 统一扁平或纸片画风；代码生成 SVG、简单几何图层、UI 和特效。关键背景或难以程序绘制的角色使用图像模型。
- 同类角色可以共用身体结构，使用不同头饰、武器、轮廓和动作建立可辨识对应；每个角色的独有行为仍完整实现。
- 待机、移动、受击、后坐和死亡可通过关键帧、图层变换与程序动画实现。只有确实需要独立轮廓的状态增加图像。
- 检查的是导入后能否辨认角色与状态、动作是否自然、边缘是否干净。减少图片调用并不自动代表美术验收通过。
- 背景音乐和关键音效可以尝试音符、节奏与合成参数的本地渲染；如效果不达标，再使用选定服务或可再分发素材。

所有游戏专属 SVG、动画参数、单位与关卡配置均在生成运行内产生。提前准备的内容限于通用引擎能力、渲染工具、导入工具和参考资料，不预置塔防实现。

### 3.2 执行器处理确定性工作

- 计划和缺陷判断使用模型；调度、清单校验、构建、切图、图集打包、输入回放和数值断言由程序执行。
- 模型读取失败摘要、有关代码与必要画面；避免反复发送整份项目、完整日志和全部历史。
- 角色保持职责划分，按有界任务启动会话。需求已冻结后，设计角色按需处理问题；不要求各角色持续相互对话。
- 按完整模块或可验收增量分配写任务，减少每个小文件都建立会话、合并和模型审查的开销。
- 依赖、数值与媒体格式先做程序检查；独立模型审查用于可运行增量、交付候选及失败诊断。最终客观验收与用户试玩保持完整。

### 3.3 同时验证规则、输入与真实渲染

- 全量内容与规则通过固定随机种子、固定模拟步长和断言覆盖。
- 浏览器正常鼠标输入覆盖界面、模式入口、购买、解锁和跨关存档等关键流程。
- 动画、音频、帧率与稳定性保留原速渲染检查，包括既定的至少 30 分钟无尽运行。
- 加速测试使用与生产相同的模拟实现；先比较原速与加速下的事件顺序、数值、冷却、胜负和存档结果，再采信加速证据。

Phaser 的 HEADLESS 省去画面，仍依赖 DOM，不能独自证明输入和渲染合格。[Phaser 文档](https://docs.phaser.io/api-documentation/namespace/phaser#headless)

Playwright 的 `fastForward` 对到期定时器至多触发一次；`runFor` 会执行时间回调。这些接口本身不证明游戏物理和动画等价，不能只把时钟快进就宣布完整通关。[Playwright 时钟文档](https://playwright.dev/docs/api/class-clock)

## 4. 更低额度可容纳什么调用量

按全部高峰、所有输入不命中缓存估算。DeepSeek 每百万输入 ¥2、输出 ¥8；图像候选用 Flash 1K 每张 $0.067 和 Pro 1K/2K 每张 $0.134。美元按 7.5 的规划系数换算，非实时汇率。[DeepSeek 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[图片价格](https://ai.google.dev/gemini-api/docs/pricing)

| 调用额度示例 | ¥100 | ¥200 |
| --- | ---: | ---: |
| 累计输入 / 输出，包含推理和返工 | 12M / 1.5M | 25M / 3M |
| 模型费用 | ¥36 | ¥74 |
| 付费图片，包含废稿 | 64 张 Flash | 120 张 Flash + 12 张 Pro |
| 图片输出费用 | ¥32.16 | ¥72.36 |
| 图片输入、文本、音频等预留 | ¥10 | ¥15 |
| 小计 | ¥78.16 | ¥161.36 |
| 剩余额度 | ¥21.84 | ¥38.64 |

左侧相当于约 600 次请求、平均 20k 输入和 2.5k 输出；右侧相当于约 1,000 次请求、平均 25k 输入和 3k 输出。这是说明额度能容纳多少请求，不能推出这些请求足够完成游戏。

64 张图片可能少于最终角色数，因此 ¥100 方案必须依赖程序绘制、图层组合和有依据的部件复用。若用户不接受样板观感或实际废稿率高，该方案就未通过验证。图像服务选型和可用性仍需实测。

成本总计还必须包括新增云端算力、音频及其他实际调用；新增费用挤占同一额度。示例没有另计租用专属 GPU，默认使用现有本机和按调用计费的服务。

## 5. 便宜不一定快：时长容量检查

下表把输出 token 总量除以总时限，得到最低累计平均输出速度。它没有扣除工具、排队、素材和验收时间，也不是供应商性能测量。

| 累计输出量 | 6h 所需 token/s | 12h 所需 token/s |
| --- | ---: | ---: |
| 0.6M | 27.8 | 13.9 |
| 1.5M | 69.4 | 34.7 |
| 3M | 138.9 | 69.4 |
| 上轮示例 8M | 370.4 | 185.2 |

串行依赖会进一步限制速度。实际关键路径为：运行计划 → 公共规则与接口 → 并行内容、模式与素材 → 集成 → 跨模式验收 → 定向修复 → 最终验收与打包。

应记录每次调用的排队/首响应、输出、工具等待和失败重做，并按任务依赖还原关键路径。由小探针推算的区间不得描述成 P95 成功时限。

## 6. 先行探针：累计最多 ¥30

沿用已有 ¥150 验证总额，建议分两步释放。A 的直接 API 与局部规则测试已执行，尚需 pi 接入；B 的完整关卡、美术及模拟等价性仍待执行。

### A. 工具与时延探针，最多 ¥10

- 使用代表性任务比较串行与有限并发，记录用量、首响应、结束、工具等待、错误及费用。
- 覆盖多轮工具调用、一次无工具回复、恢复和截图判断，不测试无关供应商。
- **通过条件：**能从记录重建账本与调用链；指定模型无静默替换，工具结果不丢失；得到实际输入/输出与有效吞吐。

### B. 有限端到端探针，累计最多 ¥30

- 从通用模板生成一个可运行关卡，覆盖资源产出、投射物、护甲或特殊状态、胜负、重开与存档；选择至少一种会挑战普通地面逻辑的机制。
- 生成并导入代表性原创角色动作，包含背景音乐和关键音效；独立验收后完成一次定向修复。
- 对相同输入比较原速与加速模拟；注入一个错误数值和一个输入故障，验证对应检查确实失败。
- **通过条件：**无预置游戏专属实现；功能和媒体可检查；记录可用资产成本、废稿、修复、耗时；正常输入与模拟检查均能揭示预置故障。

示例调用量：2M 输入、0.5M 输出按高峰约 ¥8；16 张 Flash 图约 ¥8.04；另留 ¥5 其他调用，合计 ¥21.04，余 ¥8.96。图片输入、音频和实际工具收费均要记账，超额即停。

建议这次有限切片的挑战时限先设 90 分钟；这是探针的停止条件，不是全量外推比例。如果工具链尚未准备好，先完成通用验证工具，不把其开发耗时假装成成熟产品单次生成耗时。

## 7. 收紧上限的判据

- 费用按固定开销、机制族、资产类、集成与验收分别外推；时长按依赖关键路径外推。不把首关成本直接乘 50，也不把总时长直接除以 agent 数。
- 用于外推的样本要覆盖普通角色以外的复杂机制；未经测量的模式与高风险交互单列，不能藏在一个统一平均值里。
- 保守估计仍可进入 ¥200/12h 才把它作为首轮完整运行挑战；若只能进入成本但不能进入时限，应说明是哪段阻塞。
- 首次完整运行同时检验候选额度、候选时限和原定内容清单。切片成功只允许进入下一步，不能宣布完整目标可达。
- ¥100/6h 优化目标需要完整运行证据支撑后才能成为稳定产品指标。

## 8. 对现有 spec 的影响

- 成本和时限决策已收敛，按新上限同步发布规范与任务，保留已完成的结构审查结论。
- 在 COS-03 记录时延与用量；COS-04 按部件与动作测资产成本；COS-08 增加模拟等价性；COS-10 测量生成增量与一次返工。
- 共享预算、取消恢复、独立验收与完整内容分母仍是必需能力。
- 减少常驻角色对话和细碎串行审查；修改后的检查分层应保证失败仍能被发现。
