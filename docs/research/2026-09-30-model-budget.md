# 模型、内容基准与预算依据

调研日期：2026-09-30。以下为文档和源码核实，尚未执行付费调用。金额属于计费算例和候选上限，实际用量需通过验证切片测量。

2026-10-01 更新：用户要求重评 ¥800/48h。本文件保留先前算例，新的调用额度和验证办法见 [二次穿刺](2026-10-01-cost-latency-challenge.md)；历史用量假设不能当作必要成本或必要工期。

## 1. DeepSeek 与 pi

已核实用户指定的 DeepSeek V4.1 Flash。正式 API 标识为 `deepseek-flash`，支持图片输入；其输出为文本，美术位图需要独立工具。[官方模型与定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[官方模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)

本次查看的 pi 提交已有原生 DeepSeek provider，可配置 `DEEPSEEK_API_KEY`；适配器包含推理内容回传及图片消息处理。应优先验证这条现有接入路径。[provider 源码](https://github.com/earendil-works/pi/blob/0582d9c11da78c1812d4537af2d194f1dd060d26/packages/ai/src/providers/deepseek.ts)、[适配源码](https://github.com/earendil-works/pi/blob/0582d9c11da78c1812d4537af2d194f1dd060d26/packages/ai/src/api/openai-completions.ts)

思考模式携带 tools 时，后续请求需要保留历史 assistant 的完整 `reasoning_content`，包括没有实际工具调用的轮次。这需要纳入会话继续、压缩和恢复的兼容性验证。[思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)

视觉输入按尺寸计费，当前每张最多 1024 token；细小文字与局部缺陷应结合裁剪验证。支持视觉不代表已经证明能稳定识别游戏缺陷。[视觉文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)

建议 agent 调用云端 API，本地承担构建、浏览器试玩和素材处理。RTX 3060 6GB 的本地图像生成能力尚未测试，也不能由激活参数量推导出可本地部署完整 DeepSeek 模型。

## 3. 单次完整生成的透明算例

假设整个运行累计 1 亿输入 token、1,000 万输出 token；计入所有 agent、修复、历史重放和推理输出，不依赖缓存优惠。美术假设产生 600 张普通候选图和 150 张较高单价候选图，包括修改与废稿。候选图不等于最终可用资产，也不等于动画帧数。

| 项目 | 计算 | 金额 |
| --- | --- | ---: |
| DeepSeek | 全部按高峰，100 × ¥2 + 10 × ¥8 | ¥280 |
| 图片输出 | (600 × $0.067 + 150 × $0.134) × 7.5 | ¥452.25 |
| 其他服务预留 | 图片服务的输入/文字费用、音频等，尚非报价 | ¥150 |
| 算例合计 | 上述三项 | ¥882.25 |

7.5 是用于规划的美元预算换算系数，包含一定余量，不是实时汇率。素材服务、动画方案或调用量改变时，应重新计算。

这份算例不包含租用专属 GPU、购买游戏、美术外包、商业素材包或 Cosmos 系统开发期间的全部迭代费用。默认使用按调用付费的服务和现有本机；若需要其他资源，将其加入同一总额度并重新估算。

## 4. 已确认额度与调整

- **能力验证：合计 ¥150。**用于模型工具链、一个完整关卡和少量角色动画的验证。
- **正式单次生成：硬上限 ¥800。**用户选择此档，先前约 ¥882 的计费算例已高于该额度，需要减少调用或调整分配。
- **80% 提示。**计算已结算费用与在途请求预留，达到上限后不再派发付费请求；加额由用户决定。

正式运行初始分配建议：模型 ¥240、美术 ¥300、其他服务 ¥60、返工余量 ¥200，共 ¥800；允许在总额度内调配。美术优先使用关键帧、图层和程序动画，复用已验收产物，减少逐帧生成和盲目重做。

适应该额度的示例：累计 70M 未缓存输入、8M 输出按全高峰为 ¥204；400 张 $0.067 图片和 60 张 $0.134 图片按 7.5 换算为 ¥261.30；另预留 ¥60，总计 ¥525.30。它依旧是调用量假设，不是实际预测，不能据此保证完整内容达标。

验证期候选分配：模型 ¥40、美术 ¥80、其他 ¥10、余量 ¥20，共 ¥150。所有验证子任务共用额度；不得通过创建新任务重置消费记录。

48 小时是运行时限，不能直接换算成 token 费用。任务吞吐、上下文规模、并发和重试会改变总量。Harness 需要记录使用量、适用单价和实际账单差异。

## 5. 内容基准的证据边界

用户已选择经典 PC 版主要内容全纳入，GOTY 新增项另列。官方 Steam GOTY 页面列出 50 冒险关、49 植物、26 僵尸以及冒险、迷你游戏、解谜、生存和禅境花园五类模式。这些数字用于建立待核对清单，不能直接充当 2009 PC 首发版的精确名册。[官方商店页](https://store.steampowered.com/app/3590/)

EA Readme 列出 20 项迷你游戏、砸罐子与我是僵尸各 10 项（各含无尽）、11 项生存（含无尽），并描述商店、图鉴、解锁与存档。但该文件实际标注 1.0.40、2012-10-17 构建和 Mac 系统要求，不能据此断言全部细节等同于首发 PC 版。[EA Readme](https://akamai.cdn.ea.com/eadownloads/u/f/manuals/GAME-PVZ/en_US_readme.html)

Steam 的 GOTY 公告列出新增成就、Steam Cloud 和 Zombatar；这些列为独立候选项。[官方 GOTY 公告](https://store.steampowered.com/oldnews/4183)

建议完整内容清单包含冒险二周目、特殊关、单位交互、商店经济、解锁、存档和各模式规则。逐关出怪与精确数值仍需核对。无尽模式通过指定长度运行、循环规则和增长规律验收，不能声称穷尽所有局面。

## 6. 优先验证项

1. 多轮工具调用、无工具轮次、会话压缩及恢复后推理字段仍符合接口要求。
2. 在截图与裁剪中识别预置的遮挡、溢出、错误数字；记录漏检和误报。
3. 图像服务的角色一致性、透明边缘、导入效果、动作连续性及单位成本。
4. 中断后的任务与产物恢复、在途付费请求核对、并发预算预留。
5. 用切片测量生成、修复、试玩和验收的总耗时，再估算完整内容是否能进入 48h。
