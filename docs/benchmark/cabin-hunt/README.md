# 小屋寻物

玩家在同一个房间里用鼠标找到蓝色水晶、金钥匙和红色齿轮，集齐后点门获胜。右侧的门、左侧的当前进度与最近保存、底部四个按钮贯穿整局。运行捕获[设计](design.json)和[执行验收计划](acceptance-plan.json)供后续角色实施。本文说明两份文件的玩法与操作顺序。游戏生成、浏览器实测与最终试玩结果须由各自运行产生。

唯一需求来源为 [2026-10-26 已确认的 v2 草稿](../../../.cosmos/public-validation/room-20261026-12/run/requirements/v2/draft.json)。原始记录标识为 public-room-20261026-12、revision 2，草稿文件 SHA-256 为 94cbc9603c4aa264eabf21a3709bd0a05ccb02281b21f7926c47b72d274a34ae。该链接指向保存了原始证据的本机工作区，仓库仅跟踪本设计样本。该运行记录含原始简报、8 组问答、12 项客观条目与 4 项体验要求。两份设计文件从 R38 作者设计及 R29 design/v2 捕获的计划修订，后者与 R38 所带计划内容一致。R38 的十条反馈和 R36 最终审查中的存档顺序、坐标、界面文字与音频观察问题均在本样本内处理。R40 独审反馈涉及的形色、遮挡、联网断言与体验原文已写入两份捕获文件。执行计划沿用该案例的 requirement-bundle/v2 引用，实际运行时由宿主核验绑定。

## 房间与状态转移

在 1280×720 的验收视口，三件物品的鼠标中心分别为 (468,468)、(648,518)、(828,468)，各有独立中文标签。空白点 (950,80) 在 HUD、门和交互区域之外。美术用暖色卡通背景，门有闭合与打开两帧。物品名称随图一起消失，其固定布局容器保留原尺寸。胜利卡片位于门左上方，四个按钮始终在其下方。具体边界见设计中的布局尺寸。

| 玩家操作 | 界面和存档如何变化 | 声音如何变化 |
| --- | --- | --- |
| 点击未收集物品 | 加入集合，物品从房间移出，中文列表与 n/3 同步。第 3 件使门打开，仍需点门获胜。 | 开声时播放一次收集声，首次有效点击同时启动循环音乐。 |
| 点击已收集物品原位置或空白处 | 集合、列表、进度不变，可以继续游玩。 | 无新增音效。 |
| 点击门 | 0/3、1/3、2/3 时显示“门锁着，请集齐三件物品。”；3/3 时显示“寻物成功！”与“已收集 3/3”。再点已显示面板的门保持胜利。 | 仅开声且面板由关到开时出一次开门声。 |
| 保存 | 单一槽位覆写为当前集合，最近保存当场更新中文名称和数量。0/3 空集合也是有效存档。面板开关与当前集合保持原样。 | 不触发物品或门音效。 |
| 继续 | 无档时按钮可见禁用，坐标点击不产生变化。有档时以保存集合替换当前集合，清提示、关面板、重绘物品和门，最近保存仍为原整行；恢复 3/3 时门开且面板关闭。 | 依开关保持循环播放或静音。 |
| 重新开始 | 无需确认，立即删档、清集合与面板，三件回到原位，门关、0/3、列表空，最近保存为“暂无存档”，继续禁用。 | 保留声音开关与本页媒体累计计数。 |
| 切换声音 | 标签在“声音：开”和“声音：关”间切换，集合与存档保留。 | 全部统一静音；重新开声只恢复循环音乐。若新文档第一击即关闭，始终没有输出。 |

开局默认声音开。禁用的继续作为鼠标坐标输入可以实际点到，浏览器不会向业务处理器交付有效点击。首次无档启动先查状态并尝试该按钮；有档重开先查最近保存、继续可用和静态布局，点击继续前的当前集合、进度与门态均无验收期望。

步骤编号的 s 前缀属于第一份文档，r 属于第二份。表内三个计数依次表示本页真实 BGM、收集声、开门声的累计输出激活次数。进入输出一次才加一，循环周回、保存、成功继续及重新开始本身不会重启已经循环的音乐。截图、只读观察与选择器查找均不构成鼠标输入。

| 阶段与步骤 | 实际操作和检查点 | 激活计数 |
| --- | --- | --- |
| 首次加载 s001–s051 | 三路音频已解码但未启动。检查首屏，在收集前点禁用继续，仍是无档、0/3 与空列表。 | 0 / 0 / 0 |

| r159–r192 | 完成满档继续后再重置，三件全收且不保存，点门进入无档胜利。继续仍可见禁用，点后保持胜利；面板内保存后最近保存为满集合且继续可用。 | 末值 1 / 6 / 3 |

### 浏览器实测判据

两份 JSON 随设计捕获交付。美术依据设计中的尺寸、主色和轮廓创作本地帧。宿主按执行计划在 1280×720 的实际页面截图中采样；每个物品的 96×96 色形网格包含主色、镂空及外部背景区。首屏 s019–s021、首进程重置后的 s156–s158 与第二进程重置后的 r079–r081 复用同一基准。部分继续后的 r038a、r038b 检查已收集两件的原位已清空，r039a 检查恢复的红齿轮；闭门与开门帧分别在 s034、s126 和 r133 测量。

s033 和 r081a 分别检查 HUD 各行、门、四个按钮、三个命中区及三个中文标签完整显示且互不遮挡。r020 只检查静态界面；r022–r024 对照常驻的物品槽位，不提前断言有档启动时的当前集合。胜利时 s125、r132、r177 核对面板、静态界面及四个按钮的可见面积与启禁。真实点击、原位置和锁门提示的断言继续验证操作结果。首屏、锁门及胜利阶段检查可见的倒计时、失败等排除文案和计时器；每个阶段只有鼠标输入。两段末尾 s201、r193 检查本段从导航起的宿主外部请求累计数等于零。确认的四项体验原文、试玩步骤和期望收录在捕获的 design.json 中。
