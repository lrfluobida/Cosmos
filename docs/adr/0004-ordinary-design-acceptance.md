# 普通需求确认与执行验收计划分开固定

状态：accepted，2026-10-21；共用设计 `c4dcb56fc625322232733f44e4a63e0a34b3b406` 经 `ordinary_intake_spec_reviewer` 独审 `APPROVED_DESIGN`、无P1/P2，Root已批准 [COS111](https://github.com/lrfluobida/Cosmos/issues/112#issuecomment-6298548379) / [COS112](https://github.com/lrfluobida/Cosmos/issues/113#issuecomment-6298549546)。本次仅集成设计文档，源码分阶段实施。见[设计](../specs/ordinary-design-intake.md)。

用户确认完整需求、客观验收条目与体验要求；运行时 design 在原生成时钟内产出具体执行计划。主机捕获计划，原独立 design reviewer 批准后，下游角色和可信 browser host 使用同一固定版本。体验要求保留在完整确认来源，交付报告及最终真实试玩决定绑定该清单。

继续在访谈阶段固定 selector/坐标会要求需求作者提前决定尚不存在的设计。一次引入通用自适应执行语言则扩大观测、权限和恢复契约。选择复用现有设计 capture/review/consumer，只将职责分开；动态随机决策和严格计时缺口仍明确拒绝，不降低自动要求。

持久输入必须有主机选择的版本。新默认只在 A/B 接线完整后发布，旧 origin 和旧确认保持原解释，避免平台升级改变已确认范围、批准证据或执行权限。
