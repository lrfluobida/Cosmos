# Batch 02 implementation plan

> Use superpowers:subagent-driven-development. Each task has an independent implementer and reviewer; `batch02_merger` integrates only reviewed commits.

## Goal

Connect pi to the chosen model, persist run and budget state, and produce repeatable browser acceptance evidence.

## Architecture

Build on the reviewed COS-02 contracts and COS-05 CLI. The model adapter has no authority to decide budget admission; a single local runtime service owns state and the shared ledger. Browser acceptance uses normal input and fixed artifact versions, with deterministic checks and visual evidence kept separate.

## Ownership

| Task | Paths | Required behavior |

| COS-06 / #7 | `src/runtime/store*`, `src/runtime/run*`, `src/budget/**`, `tests/runtime/**`, `tests/budget/**`, `docs/development/runtime.md` | Durable run/ledger state, atomic admission with in-flight reservations, hard deadline, unknown charge reconciliation and no reset on reopening |
| COS-08 / #9 | `src/acceptance/**`, `tests/acceptance/**`, `docs/development/acceptance.md` | Build/launch a fixed game project, drive normal mouse input, report assertions and artifacts, reject injected defects, record browser version/configuration |

Implementers avoid editing the CLI entrypoint in parallel. New capabilities are exported as small APIs with commands or examples documented; CLI integration follows once these APIs are reviewed.

## COS-03 sequence

- [ ] Inspect the current pi package and its SDK/provider documentation; reuse existing direct API findings.
- [ ] Write offline adapter tests for requested model, tool return matching, usage, cancellation and failure classification.
- [ ] Implement explicit workspace/session/auth configuration without loading unrelated user sessions or writing API keys.
- [ ] Add a bounded live probe which reads credentials from the process environment, reserves conservative cost, records usage and fails on truncated output.
- [ ] Run offline tests first. The coordinator runs the live probe within the shared validation ledger; paid calls do not run as part of default tests.
- [ ] Commit, independent review, fixes and merger integration.

## COS-06 sequence

- [ ] Write tests for reservation races, insufficient balance, deadline admission and reopened state.
- [ ] Persist ledger and run data as one consistent state update; preserve original identity, start time, deadline and closed request history.
- [ ] Represent reserved, settled and unknown external requests distinctly; failed or timed-out requests do not automatically release uncertain charges.
- [ ] Serialize local writes and fail closed on concurrent ownership; reserve for in-flight work before any external dispatch.
- [ ] Provide controlled import of prior validation cost and evidence, including the conservative ¥0.721771 already recorded.
- [ ] Verify no new request starts after the ¥200 / 12h generation limit or shared ¥150 validation limit; optimization target is not a hard stop.
- [ ] Commit, independent review, fixes and merger integration. Deeper crash and cancellation scenarios remain COS-12.

## COS-08 sequence

- [ ] Define a small acceptance plan and machine-readable result, tied to project and artifact versions.
- [ ] Write a passing generic normal-input scenario and separate cases for disabled input, incorrect displayed value and blocking overlay.
- [ ] Capture browser version, headed/headless mode, screenshot/log locations, actual versus expected results and page errors.
- [ ] Keep state observation read-only; tests do not change game state to pretend an action succeeded.
- [ ] Verify original-speed versus accelerated deterministic behavior before using accelerated rule evidence; do not substitute fake-clock jumps for normal input or real rendering checks.
- [ ] Commit, independent review, fixes and merger integration.
