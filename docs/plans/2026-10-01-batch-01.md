# Batch 01 implementation plan

> Use superpowers:subagent-driven-development. The user's required workflow is one dedicated implementer and independent reviewer per task, followed by one batch merger.

## Goal

Establish the reference inventory, executable task contracts and a Windows CLI that creates a generic browser game project.

## Architecture

The three tasks have separate file ownership and managed worktrees. Contracts are pure TypeScript plus machine-readable schemas; the CLI owns package/build configuration and the generic Phaser template. Reference work records evidence and unknowns without blocking unrelated platform code.

Base commit: `5d30460f2b7aebb37b8c4258bb1a26ebb19a42f7`.

## Batch integration

- [ ] Each task reviewer records spec compliance and code-quality findings against a specific commit.
- [ ] One merger merges approved commits into `main` with `--no-ff`, preserves the reviewed commit ancestry, accounts for coordinator documentation and resolves only necessary integration conflicts.
- [ ] Integrate the contracts tests into the CLI-owned package scripts and run type/build/test checks once on the merged tree.
- [ ] Update `PROGRESS.md` and GitHub issues with commits, evidence, remaining gaps and the next dependency-ready tasks.
- [ ] Push the verified batch, then continue to the next batch without asking for routine approval.
